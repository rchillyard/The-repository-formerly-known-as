# Run results from Yunlu: request 12, appendix: every full-suite row, 2026-10-05

Companion to `Run results from Yunlu 2026-10-05.md`. Every cell is `score ± error` in ms/op exactly as JMH prints it (3
decimals, HALF_UP), read from the eight per-class JSONs `req12-full-<Class>.json` (`-f 5 -wi 5 -i 10 -r 2s -w 2s`, one
invocation per class, Cnt = 50 per row, ± = 99.9 % CI half-width), followed in brackets by the 11cd score
(`req11cd-full-<Class>.json`, printed without ±) and req12 ÷ 11cd. † = the two CIs overlap; ‡ after a cell = at least
one of the row's five forks has mean(iterations 1–5) ÷ mean(iterations 6–10) > 1.10, so its score is usually above
steady state (the two exceptions are in "‡ and § rows", with steady ÷ score above 1); § = every fork has that ratio
below 0.90, so its score is below its iterations 6–10 level (main document, Marks). The label column gives each row's
coder classification: "coder changed (saturating → masking)" for an english row that reads `state.coder`, "coder changed
(ordinal → rank)" for such a chinesenames row, whose ratio is dominated by the coder's effect, "renamed" for the four
chinesenames rows of your relabelling table, compared with the 11cd row named there, "englishCoder, encode loop changed
by `f43ff52`" for the Adversarial `sharedPrefix*` husky rows, whose coder did not change but whose encode loop did (main
document, (e)), and "same code path" for everything else. "same code path" means the coder and the method body did not
change; the other `src/main` changes since `d947e77` can still affect such a row (main document, "Checkout and build"),
and the chinese husky rows and the `huskyEncodeOnlyEnglish*` rows among them also run the encode loop `f43ff52` changed
(main document, Marks). A dash marks a (method, params) row absent by design, because the benchmark throws for that
corpus (24 rows, main document, "Convergence and the absent rows"). Ratios have 2 decimals on coder-changed rows and 3
elsewhere. Generated by `runner/req12-tables.py --appendix`, outside the repo; every JSON row is printed exactly once.
